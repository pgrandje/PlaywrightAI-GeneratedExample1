# AI-Generated Simple Playwrite Test Suite


## Overview:
This suite is a simple Playwright test suite example that was used to test whether an entire suite could be generated using GitHub CoPilot.  And, it was an experiment to determine where an AI LLM could be used for efficiency gains versus where it would be just as efficient to code directly rather than continuously coming up with prompts to adjust the code for long-term viability.

## Goal
The goal was to 
- Build an example test suite that demonstrated best-practics and readability.
- Followed Page Object Model principles with all browser interactions contained in readable page object classes that corresponded to the pages in the application under test.
- Used symbol names that would be easy to read for another engineer who did not develop this code.
- Uses fixtures where appropriate
- Demonstrate examples of intercepting an API and running assertions on either the outgoing payload or incoming response.
- Used meaningful assertions with meaningful failure messages throughout the test suite.
- Have easy to read tests that mirrored user actions/workflows by calling readable page object methods that mirroed those user actions.

## The Application Under Test
For this example the tests run against a simple, public-facing, photography website:  paulgrandjeanphotography.com.
No authentication is necessary to use this site.  Authentication support within fixtures will be showing in a different test suite example to be developed in a different repository.  This example is intended as my first AI, test-generation experiement.

## Methodology
GitHub CoPilot, the free version, was used to generate this code.  The Playwright agents were added to CoPilot, however MCP was not used.  All code was generated by prompting CoPilot.  That is, the code was not touched.  The only part of the project that was directly manipulated by the engineer (myself) was this README file.  The code was however reviewed by the engineer after each prompt-response interaction.
